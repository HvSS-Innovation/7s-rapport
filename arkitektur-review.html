3. Större ändringar — mekanik & process

HTML-mall via include, inte copy-paste

Header/footer/tab-nav-sub upprepas i alla rapportsidor. När en ny tabb läggs till måste 19 filer ändras (CHANGELOG bekräftar att det redan har bett om städning).
Två vägar — välj en:
A) Build-steg: scripts/build/build-pages.js läser
   templates/header.html + templates/footer.html + reports/X.body.html
   → reports/X.html
B) Runtime: <header data-include="/templates/header.html"></header>
   + en liten fetch+innerHTML-loader i lib/include.js (ingen SSR-PWA-konflikt
   så länge SW pre-cacheas före första bruk)
Rekommendation: (A) — håller "rena HTML-sidor" i produktion.
Påverkan: Hög · stort ingrepp men botar tab-nav-divergens permanent.

Lägg minimalt build-skikt — inte Vite, inte Webpack

Vanilla-stacken är en feature. Men helt utan build-steg betyder hand-uppdaterade SW-listor, copy-pasted CSS, hand-bumpade versioner. Ett tunt npm run build löser de tre på en gång.
package.json:
  "scripts": {
    "dev":   "python -m http.server 8000",
    "build": "node scripts/build/gen-sw-files.js
              && node scripts/build/build-pages.js
              && node scripts/build/stamp-version.js",
    "audit": "node scripts/audit/check-tab-nav.js"
  }
Ingen bundler. Ingen TS. Ingen JSX. Bara
node-skript som producerar exakt det som idag görs för hand.
Påverkan: Hög · paradigm-skifte. Men förändrar inte produktionsbeteendet — bara hur du itererar.
